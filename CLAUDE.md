# CLAUDE.md — постоянные правила для агента

## Проект
iOS-приложение AI Chat (чат в духе ChatGPT) — тестовое задание. Подробности: `docs/TASK.md`, план: `docs/PLAN.md`, архитектура: `docs/ARCHITECTURE.md`.

## Стек
- Swift, SwiftUI, MVVM, Swift Concurrency (async/await), URLSession, SwiftData.
- XcodeGen: `project.yml` — единственный источник правды. `.xcodeproj` генерируется, не коммитится.
- Зависимости только через SPM. CocoaPods запрещён. Сторонние библиотеки — только при реальной необходимости.
- AI: OpenRouter, Chat Completions API со streaming (SSE). Модель — из конфигурации.

## Ограничения iOS
- Минимальная версия — iOS 18.0. Deployment target в `project.yml` = 18.0.
- API новее iOS 18 — только с проверкой `#available` и альтернативной реализацией для iOS 18.

## Архитектурные правила
- Views не содержат сетевой и бизнес-логики. Логика — во ViewModels и сервисах.
- Сеть отделена от UI через протоколы (`AIProvider` и др.). Провайдер и модель меняются конфигурацией.
- UI-обновления — через `@MainActor`. Задачи (`Task`) отменяются явно.
- Не делать больших View. Не дублировать бизнес-логику. Избегать force unwrap. Не оставлять неиспользуемый код и TODO в критичных функциях.

## Правила Git
- Conventional Commits: `type(scope): description`. Запрещены сообщения: update, changes, fix, done, final, test.
- ПЕРЕОПРЕДЕЛЕНО ВЛАДЕЛЕЦЕМ: коммиты и push делает владелец вручную. Агент готовит изменения, список файлов и текст коммита, затем останавливается и ждёт.
- Перед каждым коммитом (подготовкой): `git status`, `git diff`, `git diff --cached`. Добавлять файлы только конкретными путями, без `git add -A`.
- Не включать незакоммиченные изменения владельца в свои коммиты.
- Запрещено: `reset --hard`, `clean -fd`, `push --force`, `push --force-with-lease`, переписывание истории, самовольное переключение веток, удаление веток и коммитов.
- Не создавать пустые коммиты.
- Не удалять файлы владельца без разрешения. Изменения индекса (`git rm --cached`) — только с подтверждения.

## Ключи и секреты
- Ключ API не в открытом виде в исходниках, не в git, не в README, не в AI Logs, не в выводе терминала и логах.
- Не придумывать ключ. Если ключа нет, использовать заглушку конфигурации и явно сообщить, куда его положить.
- Не заявлять, что интеграция проверена, пока реальный запрос не выполнен и не проверен.

## Правила тестирования
- Unit-тесты не зависят от реального ключа и лимитов. Используется mock `URLProtocol`.
- Фиктивных AI-ответов в приложении нет. Не имитировать streaming искусственными задержками.
- Перед переходом к следующему этапу: сборка проходит, тесты этапа запущены, ошибки исправлены.

## Запрет на фиктивные реализации
- Нельзя выдавать нереализованные функции за готовые. Заглушки явно помечаются в отчёте.
- Ошибки не скрываются.

## Цикл этапа
Реализация → проверка кода → сборка → тесты → исправление → повторная проверка → git diff → список файлов для коммита и текст коммита → ожидание владельца → отчёт.
