## Правила процесса (переопределены владельцем)

- Коммиты и push делает владелец репозитория вручную. Агент готовит изменения, список файлов и текст коммита (Conventional Commits), а затем останавливается.
- Работа идёт по этапам. После каждого этапа — отчёт и ожидание подтверждения.
- Деструктивные git-операции (`reset --hard`, `clean -fd`, `push --force`, переписывание истории) не выполняются. Незакоммиченные изменения владельца не включаются в коммиты агента.
- Сборка и симулятор работают на macOS. Агент запускает их через подключённую папку, либо владелец запускает `Build.command` и присылает вывод.

## Открытые вопросы

   - (B) ключ в локальном файле, исключённом из git (например, `Secrets.xcconfig`), но включённом в zip-архив вместе с папкой проекта. Ключ не попадает в git, приложение работает без настроек после распаковки архива.

## Этап 07 — сделано (ожидает сборки на Mac)

- `MarkdownBlockParser` (Utilities): блоки заголовков (# … ######), маркированных и нумерованных списков, блоков кода с ``` (незакрытый блок до конца текста — для потоковой генерации), абзацев.
- `MarkdownView`: отображает блоки; строчная разметка (жирный, курсив, `код`) через системный `AttributedString`, переводы строк сохраняются. Внешних библиотек нет.
- `MessageView`: пользователь — пузырь справа; ассистент и системные — Markdown на всю ширину.
- `ChatView`: автоскролл вниз при новом сообщении и при изменении текста последнего сообщения; `defaultScrollAnchor(.bottom)`; скрытие клавиатуры при прокрутке.
- Проверка сейчас — через Preview `MarkdownView` (пример разметки, не ответ ИИ). Реальный поток проверяется на этапе 12.
- Известное ограничение: при потоковой генерации блок может сменить тип (абзац → список), что даёт небольшой сдвиг. Устраняется на этапе 16.

## Этап 08 — сделано (ожидает сборки на Mac)

- `PersistenceController`: схема `Chat` и `Message`, контейнер SwiftData. Для тестов поддерживается `inMemory`.
- `SwiftDataChatRepository`: реализация `ChatRepository` на `ModelContext`. Список чатов сортируется по `updatedAt` (новые сверху).
- `AIChatApp` создаёт контейнер и передаёт его через `.modelContainer`. Если хранилище не открылось, приложение останавливается с сообщением: тихо терять историю нельзя.
- `ContentView` открывает последний чат. Если чатов нет, создаёт первый. Поэтому после перезапуска чат восстанавливается.
- Временный `InMemoryChatRepository` удалён.
- Ограничение: сообщения в UI пока не создаются (отправка на этапе 11). Порядок сообщений и восстановление переписки проверяются модульными тестами на этапе 17 и сквозной проверкой после этапа 11.

## Этап 09 — сделано (ожидает сборки на Mac)

- Кнопка списка слева открывает историю (лист) с чатами, сортировка по `updatedAt`, свежие сверху. Список обновляется при открытии.
- Переключение: нажатие на чат открывает его и закрывает историю. Текущий чат отмечен галочкой.
- Новый чат: кнопка справа. Если текущий чат пуст, новый не создаётся.
- Удаление: свайп влево → подтверждение «Удалить чат?». Если удалён открытый чат, открывается следующий, а если чатов не осталось, создаётся новый.
- Автоназвание: `Chat.adoptTitleIfNeeded(fromFirstMessage:)` берёт первое сообщение (до 40 символов). Вызов добавится в отправку на этапе 11, потому что сейчас отправки нет.
- Ограничение: `updatedAt` чата обновится при отправке сообщений (этап 11). Сейчас сортировка по дате создания.
- Проверка сейчас: создать несколько чатов, переключаться, удалять с подтверждением, перезапустить приложение.
